Franklin County Dasymetric Mapping

Fine-grained population and employment disaggregation using land cover weights.

Role
Data Scientist  ·  GIS Analyst
Client / Context
CDM Smith Inc.  ·  Columbus, OH

The Challenge

Government statistics like employment counts and household totals are usually published at coarse geographies, often no finer than a county, but spatial analysis needs those totals broken down to much finer sub county zones. Simply dividing a county total evenly across its zones assumes uniform density, which is wrong, since dense urban zones and rural zones don't hold the same amount of activity per acre. Getting a defensible fine grained estimate runs into several real problems. Employment data arrives as establishment level records with wildly varying location precision, some carry rooftop level geocoding, others resolve only to a ZIP code or not at all, and a meaningful share of records are administrative noise rather than real workplace locations, duplicate headquarters listings, remote work entries with no fixed location, and staffing agencies whose payroll doesn't reflect where people actually work. Household counts come from a separate Census product published at the county level only, and whatever fine grained values get produced have to add up exactly to the original county totals, or the estimate isn't defensible.

Solution

I built three linked ArcGIS Python Toolboxes forming a disaggregation pipeline, employment preparation, household allocation, and a final composite density calculation, so each stage can be run and reviewed on its own before feeding the next. I built this solo, as part of the same statewide automation effort as the parcel ETL pipeline and terrain preprocessing tools.

Method

The pipeline moves from cleaning raw records through disaggregation to a final composite metric, with a validation pass at the end checking every number against its own control total.

Cleaning and classifying employment records

Employment establishment records are cleaned first, removing headquarters duplicates and telecommuter listings, and redistributing temp staffing employment based on documented share splits. Each record is then classified into standard categories via industry code lookups against a configurable classification table, with explicit overrides for government and K-12 employers.

Point-in-polygon with a dasymetric fallback

Records with reliable point level geocoding are assigned directly to their containing zone through a spatial join. Records with only coarse geocoding fall back to dasymetric allocation, spread across a county's zones weighted by each zone's share of developed land in the matching land use category, rather than dropped or assigned arbitrarily.

Disaggregating household totals

Household totals come from an American Community Survey table published at the county level. I built a parser for the raw Census CSV export, handling its specific label rows, geography ID format, and margin of error columns, then allocated each county's total down to its zones proportionally by residential developed acreage, the same dasymetric logic used as the employment fallback, but as the primary method here since no point level household data exists. Not every area has land use data of the same quality, so zones flagged as lower confidence use geographic area as a fallback weight instead, decided by a majority rule check on each county.

Reconciling and building the final metric

Proportional allocation produces fractional values that don't sum to whole numbers on their own, so every zone is rounded down and the rounding remainder is distributed to the zones with the largest fractional leftover, one at a time, until each county's zone values sum to exactly its original control total. Once employment and household estimates exist at the zone level, they're combined with each zone's acreage into a single composite activity density metric, then bucketed into ten classes so each class represents an equal share of total activity rather than an equal number of zones.

Technical Highlights

  • Language / Platform: Python, ArcGIS Pro (arcpy) Python Toolboxes, pandas and numpy for tabular processing
  • Data sources: State employment establishment micro data, American Community Survey housing tables, land use acreage from a prior parcel classification stage
  • Data cleaning: Duplicate and headquarters record removal, telecommuter filtering, proportional redistribution of ambiguous employment categories
  • Spatial methods: Point-in-polygon spatial join for precisely geocoded records, dasymetric proportional allocation for everything else, majority rule tiered weighting for reliability
  • Reconciliation: Exact integer rounding reconciliation so disaggregated values always sum to published control totals

Outcome

Fine grained employment and household estimates only earn trust if they can be traced back to a real methodology and reconcile to numbers a data consumer can independently verify.

  • The disaggregation falls back gracefully when precise data isn't available, rather than dropping records or assigning them arbitrarily.
  • Every fine grained value reconciles exactly to its published county control total, so the estimate is defensible in aggregate, not just approximately close.
  • Every classification and validation decision is logged, so the fine grained output can be handed to someone else and defended, not just used as an internal black box number.
